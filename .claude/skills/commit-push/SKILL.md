# 커밋 & 푸시

작업 내용을 커밋하고 원격 저장소에 푸시하는 기본 절차.

## 절차

1. **상태 확인**
   - `git status --short`와 `git branch --show-current`로 변경 파일과 현재 브랜치를 확인한다.
   - 기본 브랜치(main/master)라면 먼저 작업 브랜치를 만든다.

2. **커밋할 파일 점검**
   - `git diff`로 변경 내용을 확인한다.
   - `.env`, 인증 정보, 키 파일 등 비밀이 담긴 파일은 커밋하지 않고 사용자에게 알린다.

3. **커밋**
   - 변경 사항이 있으면 관련 파일만 `git add`로 추가한다.
   - 커밋 메시지는 무엇을 왜 바꿨는지 한 줄로 요약한다. (예: `Add tomorrow's to-do manager page`)
   - 변경 사항이 없고 이미 커밋돼 있다면 커밋을 건너뛰고 푸시만 한다.

4. **푸시**
   - `git push -u origin <현재 브랜치>`
   - 네트워크 오류면 잠시 기다렸다가 최대 4번까지 다시 시도한다.
   - 원격에 내가 없는 커밋이 있어 거부되면 강제 푸시하지 말고 `git fetch origin <브랜치> && git merge --no-edit FETCH_HEAD` 후 다시 푸시한다.

5. **결과 보고**
   - 커밋 해시와 메시지, 푸시한 브랜치, GitHub 브랜치 링크를 사용자에게 알려준다.
   - 사용자가 요청하지 않으면 PR은 만들지 않는다.
